\## Task 2: Heavyweight, Lightweight, or No Process at All?



\## Three Weaknesses



* Requirements are not documented the team lead verbally gets the requirements from the client and doesn't document them the proceeds to verbally tell the team based on a conversation they half remember. this leads to requirements not being completed and/or forgotten about. The requirements not being documented is complete absence of any disciplined process.



* Code is pushed directly up on the main branch with no code review from another developer this lack of reviewing bypasses many safety checks and risks breaking the stable production system. Using an agile approach would prevent this as the team would develop incrementally creating feature branches for each different increment.



* Testing isn't done the only 'testing' completed is the developer who created the code trying it themselves then moving on to the next task. This leads to many bugs. During agile development testing is complete after every increment allowing for the feature to be added into the main branch before the next increment so this would reduce the amount of bugs they would get and improve the testing.
